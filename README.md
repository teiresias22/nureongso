# 누렁소검은소

국회의원이 **무슨 공약을 했고 얼마나 지켰는지**, **법안을 얼마나 발의하고 남의 법안에 서명했는지**를
유권자가 한눈에 볼 수 있게 하는 프로젝트. 선거 공보물만으로는 N선 의원의 지난 임기 성적표를 알 수 없다는
문제에서 출발했다.

## 지금 되는 것

**국회의원 (22대, 데이터 적재 완료)**
- 현역 299명 목록 — 정당·지역구·직위 검색, 지역구/비례 구분, 발의 순 정렬
- 의원 상세 — 대표발의, 공동발의, 가결률, 본회의 표결 참여율과 찬반 분포, 법안 목록
- 법안 상세 — 대표발의자 / 공동발의자 전원, 본회의 표결 집계

**단체장·교육감 (2026 지방선거, 적재 완료)**
- 시도지사 16, 교육감 16, 기초단체장 227 — 총 259명, 공약 1,280건
- 공약 원문(목표·이행방법·이행기간·재원조달)까지 들어있다

화면은 직위가 아니라 **실제 데이터 유무**로 갈린다. 발의·표결 기록이 있으면 의정활동을,
공약이 있으면 공약을 보여준다. 국회의원이었다가 단체장이 된 사람은 한 인물로 합쳐지므로
직위로 가르면 과거 발의 이력이 사라진다.

**공약 (선거공보 PDF → LLM 구조화)**
- 선거공보 509건 수집, 공약 9,218건 추출
- 텍스트가 (cid:NNNN) 으로 깨지는 공보(66건)는 PDF 원본을 모델에 직접 넘긴다

이행도 판정은 아직 없다. 화면에는 '미집계'·'미판정'으로 표시된다.

## 구조

```
collector/   Python 수집기 (열린국회정보 / 선관위 Open API → Supabase)
supabase/    schema.sql  (Supabase SQL Editor 에 붙여넣어 실행)
web/         Next.js (App Router) 프론트
```

## 시작하기

1. Supabase 프로젝트 생성 → SQL Editor 에 `supabase/schema.sql` 실행
2. `.env.example` 참고해 `collector/.env`, `web/.env.local` 작성
3. 두 파일 다 [dotenvx](https://dotenvx.com) 로 암호화해 둔다

```bash
brew install dotenvx/brew/dotenvx
dotenvx encrypt -f web/.env.local     # 값을 제자리에서 암호화. 개인키는 OS 키체인에 저장
cd collector
dotenvx encrypt
dotenvx get DATABASE_URL              # 값 확인
dotenvx set GEMINI_API_KEY 새값       # 값 바꾸기 (암호화된 채로 저장)
```

4. 수집 — 실행은 항상 `dotenvx run --` 뒤에 붙인다 (web 은 `npm run dev` 가 알아서 거친다)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
dotenvx run -- .venv/bin/python ingest.py all --age 22
```

`members` → `bills` → `plenary` → `votes` 순으로 돈다. votes 는 의안 1건당 1회 호출이라
22대 기준 약 1,800회, 20~30분 걸린다. 중단해도 이미 받은 의안은 건너뛴다.

> **`ASSEMBLY_API_KEY` 는 필수다.** 키 없이 호출하면 서버가 `pIndex`/`pSize` 를 무시하고
> 매번 첫 5행만 돌려주면서 총건수는 정상값을 준다. 그대로 두면 같은 행을 수천 번 수집한다.
> 수집기는 키가 없으면 시작하지 않고, 페이지가 안 넘어가면 중단한다.

4. 웹

```bash
cd web && npm run dev
```

### 실측으로 확인한 API 함정

- 열린국회정보 전체 목록(`OPENSRVAPI`, 280개)의 `SRV_URL` 은 **설명 화면 주소**다. 실제 호출
  이름(`nahfbzwvatmaxscwq` 같은 것)은 `DDC_URL` 로 받는 명세서 xls 안에만 있다. 설명 화면은
  내용을 스크립트로 불러와서 긁어도 비어 있다.
- **본회의 출결은 API 가 없다.** 목록 280개 중 출결은 하나도 없고, '파일 데이터' 로 회기마다
  엑셀이 올라온다(22대 제415회~ xlsx, 그 앞 pdf). 최신 파일에 그 대수 누적 총계가 있어 하나면
  된다. `회의일수 = 출석+결석+청가+출장+결석신고서` — 결석신고서를 빼면 11명이 안 맞는다.
- 겸직·출결은 **의원 코드 없이 이름만** 준다. `박 정`(띄어쓰기), `李達坤`(한자만),
  `최경환(崔敬煥)`, `이수진(비)` 모양이 섞여 온다. 출결표의 22대 박지원 둘은 한 명이 `朴芝源`.
- `member.name_hanja` 는 **호환용 한자**로 들어 있다(李 가 U+674E 가 아니라 U+F9E1, 790명).
  겸직 API 는 표준 코드로 보내서 NFC 로 펴지 않으면 같은 글자가 안 맞는다.

- 인증키는 **인코딩 키를 그대로** 보내야 한다. 다시 URL 인코딩하면 이중 인코딩돼
  `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 난다. `nec.py` 가 알아서 되돌린다.
- 당선인 서비스명은 `WinnerInfoInqireService`**2** 다. 2 가 빠지면 경로 자체가 없다.
- 공약 본문 필드는 `prmsCont` 가 아니라 **`prmmCont`** 다 (선관위 쪽 오타).
  제목은 `prmsTitle`, 분야는 `prmsRealmName` 으로 s 가 맞다.
- 정당정책 API 는 어떤 `sgId` 를 넣어도 `INFO-03`(데이터 없음) 만 돌아온다.
  문서의 예시값(20220309)으로도 비어 있다. 지금은 쓸 수 없다.

### 중도 사퇴자의 과거 선거공보는 구할 수 없다

정책·공약마당의 선거별 목록은 **그 의석의 현재 주인**을 보여준다. 원래 당선자가 사퇴하면
재보궐 당선자로 교체되고 원래 당선자는 목록에서 사라진다. 실측: 21대(20200415) 목록의
원주시갑은 이광재(2020년 당선)가 아니라 박정하(2022년 재보궐 당선)다.

그래서 임기 중 사퇴한 사람의 그 임기 공약은 이 경로로 받을 수 없다. 수집기 문제가 아니라
출처의 구조다. 목록에 없으니 "매칭 실패" 로도 잡히지 않는다.

### 직위마다 잴 수 있는 것이 다르다

선거공약 API 는 **선거공약서 제출 대상 직위만** 공약을 준다 — 대통령, 시도지사,
구시군의장, 교육감. 국회의원과 지방의원은 대상이 아니라 선거공보 PDF 밖에 없다.
반대로 법안 발의·표결 기록은 국회의원에게만 존재한다. 그래서 화면은 `office` 로
갈라진다. 국회의원은 의정활동 중심, 단체장·교육감은 공약 중심이다.

선거종류코드(`sg_typecode`)는 1 대통령, 2 국회의원, 3 시도지사, 4 구시군의장,
5 시도의원, 6 구시군의원, 7~9 각 비례대표, 10 교육의원, 11 교육감. `sg_id` 는 선거일(YYYYMMDD).

## 집계 기준

- **대표발의**와 **공동발의**를 분리해 표시한다. 공동발의는 서명일 뿐이라 같은 무게로 세지 않는다.
- **가결률** 분모는 대표발의 전체(계류 포함)다. 계류 건수를 함께 표시한다.
- **표결 참여율** = (전체 표결 - 불참) / 전체 표결.
- 공약 **이행도**는 어느 기관도 공식 제공하지 않는다. 이 서비스가 법안·뉴스 근거로 판정한 값이며,
  자동 판정인지 사람 검수를 거쳤는지를 항상 함께 표시한다.

## 도달 경로 — 이름과 지역, 둘뿐이다

선거공보에서 유권자가 얻는 정보는 **이름과 선거구**뿐이다. 그 둘로 이 사이트에
도달하지 못하면 아무리 기록을 모아도 작동하지 않는다. 그래서 둘 다 길을 낸다.

- **이름**: `/m/[code]` 와 `/bill/[id]` 가 각자 `generateMetadata` 로 제목과 설명을
  갖는다. 설명에는 홍보 문구가 아니라 실제 수치(대표발의·가결·공약 건수)를 넣는다.
  `sitemap.ts` 는 **현직만** 싣는다 — 역대까지 넣으면 2,285행이라 PostgREST 1000행
  상한에 조용히 잘린다. 법안 19,544건은 의원 페이지 링크로 크롤러가 따라간다.
  `metadataBase` 가 없으면 OG 이미지가 상대 경로로 나가 공유 썸네일이 안 뜬다.
- **지역**: `/my` 에서 시군구 하나를 고르면 국회의원·시도지사·구시군의장·교육감이 나온다.
  지역 키는 `member.district` 가 아니라 선관위의 `sd_name`/`wiw_name` 이다
  (`member_area` 뷰). `district` 는 직위마다 모양이 달라
  (`대구 북구을` / `대구광역시` / `검단구`) 시군구를 안전하게 뽑을 수 없고,
  구시군의장의 `광주시` 는 경기 광주시인데 광주광역시와 구별이 안 된다.
  국회의원만은 `district` 부분일치로 찾는다. `군산시김제시부안군을` 처럼 한 지역구가
  여러 시를 묶으면 `wiw_name` 에 김제시만 남아 군산시 주민이 자기 의원을 놓치기 때문이다.
  2026년 통합된 광주·전남은 시도지사·교육감만 새 이름으로 넘어와서 화면에서 합쳐 준다.

## 재산 — 선거공보가 아니라 국회공보에서

유권자가 보고 싶은 인적 정보(재산·병역·납세·전과)는 선거공보가 아니라 **별도 문서인
후보자정보공개자료**에 실린다. 정책·공약마당 목록의 문서 종류는 `선거공보` 하나뿐이고
(22대 당선인 254명 실측), 공보에 신고 면을 스스로 넣은 후보는 2024 총선 30/240,
2026 지방선거 14/269 뿐이다. 게다가 선관위는 재산·전과를 공직선거법 제49조제12항에 따라
**선거일 후 비공개**로 돌린다. 그래서 병역·납세·전과는 싣지 않는다.

재산만은 공직자윤리법 제10조의 정기 공개라 내려가지 않고 전원이 실린다. 국회공보
재산공개 호(3월 정기, 총선 해 8월 신규·퇴직)를 `asset.py` 가 받아 `asset_report` 에 넣는다.

- 정보공개센터가 같은 공보를 표로 정리해 두었지만 **CC BY-NC-ND** 라 가공해 실을 수 없다.
  국회공보는 국회사무처가 저작재산권 전부를 가진 공공저작물이라 원본을 직접 읽는다.
- PDF 가 글자라서 줄 단위로 읽힌다. 8개 호 모두 머리글 수와 `총 계` 줄 수가 같았고,
  2,382명 전원이 `항목 소계 합 − 채무 = 총계` 로 맞았다.
- 동명이인은 공보가 이름 뒤 괄호에 지역구나 한자를 붙인다(`김병욱(경기 성남시분당구을)`).
  괄호가 없으면 '최초' 등록은 그 대가 첫 임기인 사람만, 그다음 공고일 뒤 당선자를 뺀다
  (22대 박지원 둘 중 한 명은 2026-06 재보궐 당선).
- 같은 호에서 한 사람에게 두 줄이 붙으면 둘 다 비운다. 선거 이력이 빠진 사람 때문에 실제로
  그랬다 — 21대 비례 이수진은 첫 당선이 2024 로 잡혀 2021 공보의 이수진 둘이 한 사람에게 갔다.
- 빈 줄은 금액으로 잇는다. 같은 사람의 연속 신고는 앞 호 현재가액 = 뒤 호 종전가액이다
  (실측 1,745쌍 중 1,732쌍, 나머지는 장관 재임 등으로 한 해를 건너뛴 경우).
- 8개 호 2,382줄 중 2,379줄이 붙었다. 못 붙인 3줄은 2020-08 공보의 20대 퇴직의원
  김성태·김성태·최경환이다(동명이인이고 앞뒤로 이어 볼 신고가 없다).

## 공개돼 있어도 싣지 않는 것

- **병역·납세·전과**: 위와 같다. 선거 후 비공개이고, 공보에 스스로 실은 사람만 드러난다.
- **정치자금 기부내역**: 정치자금법 제42조가 공개된 기부내역의 인터넷 게시·정치적 이용을
  금지한다(2026-04 울산선관위 고발 사례).
- **외부 기관의 공약이행 등급**(한국매니페스토실천본부 등): 판정이라 재계산할 수 없다.
- **수사·재판 중 사건**: 구조화된 공식 출처가 없고 확정되지 않은 사실이다.

## 이용자 참여를 붙이지 않는다

댓글·평점·제보를 검토했고 두지 않기로 했다. 빠뜨린 것이 아니라 정한 것이다.

- 선거철에 쓰는 도구라 재방문율은 맞는 지표가 아니다. 참여 기능의 주된 효용이 그것이다.
- 이 서비스의 희소성은 "의견이 없다" 이다. 의견은 이미 넘치고 없는 것은 기록이다.
- 여기 있는 모든 숫자는 공개된 규칙과 출처로 누구나 다시 계산할 수 있어야 한다.
  이용자 의견은 그럴 수 없다.
- 검수는 영구 운영비다. 공약 판정 검수(1인, 수동)도 아직 끝나지 않았다.
- 이용자 평가를 집계해 공개하면 공직선거법 제108조의 여론조사 공표 제한에 걸릴 소지가 있다.

나중에 붙인다면 자유 게시 공간이 아니라 **출처 링크를 필수로 받는 비공개 제보 큐**,
검수를 통과한 것만 공개, 제보자와 제보 수는 표시하지 않는 형태로 간다.

## LLM 무료 한도

제미나이 무료 등급은 모델당 **하루 500건**이다(태평양 시간 자정 초기화).
분당 제한은 기다리면 풀리지만 일일 한도는 그날 회복되지 않으므로, 수집기는
둘을 구분해 일일 한도일 때는 남은 문서를 헛돌리지 않고 멈춘다. `parsed_at` 이
null 로 남아 다음 실행이 이어받는다. 같은 명령을 다시 실행하면 된다.

**키를 여러 개 쓰려면** `GEMINI_API_KEY` 에 쉼표로 이어 넣는다. 일일 한도에
걸리면 다음 키로 자동으로 넘어가고, 전부 떨어지면 그때 멈춘다. 분당 한도는
기다리면 풀리므로 키를 바꾸지 않는다.

```
GEMINI_API_KEY=AIza...첫번째,AIza...두번째
```

**다만 한도는 키 단위가 아니라 구글 클라우드 프로젝트 단위다**
(오류 코드가 `GenerateRequestsPerDayPerProjectPerModel-FreeTier` 다).
같은 프로젝트에서 키만 하나 더 발급하면 한도를 같이 쓰므로 아무것도 나아지지 않는다.
AI Studio 에서 **다른 프로젝트**를 만들거나 다른 구글 계정으로 발급해야 한도가 따로 생긴다.
